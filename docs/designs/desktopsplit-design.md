## Problem Statement

在 Windows 10 的一块物理显示器上，用户希望获得“像两块屏幕一样”的工作体验：例如把一块 27 英寸显示器按 `4/5 + 1/5` 分成两个矩形区域，让浏览器等普通窗口在所属区域内最大化，而不必连接第二块显示器，也不需要虚拟显示器驱动。

首个用户是开发者本人。工具需要轻量、开机启动、常驻托盘，并能通过设置界面调整分区数量、比例和预设布局。

## What Makes This Cool

窗口不需要被强制吸附或重新排列。用户仍然按自己的习惯拖动窗口；软件只根据窗口所在区域决定它的“屏幕归属”，并把系统最大化动作转换成当前区域内的最大化。它用很少的认知负担，把一块屏幕变成可编排的工作台。

## Constraints

- 首版面向个人使用，目标平台为 Windows 10。
- 首版只管理一块实体显示器。
- 不创建虚拟显示器，不安装显示驱动。
- 不自动吸附、不主动移动普通窗口。
- 首版不做应用级自动分配、多屏编排和任意形状区域。
- 设置界面需要展示布局预览和可拖动的分割线。
- 软件需要托盘运行、开机启动、暂停/恢复分区和显式退出。
- 当前项目不启用自动提交，也不创建 Git 提交。

## Premises

1. 用户真正需要的是“区域级最大化”，而不是真正的虚拟显示器。
2. 用窗口中心点判定区域归属，能提供简单、稳定、可解释的行为。
3. 矩形分割树足以覆盖首版的左右分区、均分、三列和后续嵌套布局。
4. C# WPF 负责设置界面，Win32 API 负责窗口状态和显示器工作区，是首版速度与控制力之间的合适平衡。
5. 个人优先意味着可以先发布便携版，不必先解决安装器、更新服务和多用户配置同步。

## Approaches Considered

### Approach A: WPF 设置壳 + Win32 窗口管理核心

采用 WPF 构建设置、预览、预设和托盘菜单；采用 Win32 互操作监听普通顶层窗口状态，维护窗口中心点对应的区域，并在最大化/恢复时应用区域工作区。布局以比例保存，以当前显示器工作区重新计算像素边界。

这是本次选定的方案。它把用户体验层与系统窗口层分开，能够快速验证个人工作流，又不会把行为锁死在某个具体布局。

### Approach B: 纯 C++ Win32 原生实现

以原生窗口消息、Shell 集成和托盘为核心，设置窗口也使用 Win32 控件。资源占用和系统控制会更直接，但预览编辑器、预设管理和后续 UI 迭代的开发成本更高，不符合当前“先解决自己的工作流”的优先级。

### Approach C: 复用现有窗口分区工具的配置/行为

借鉴或依赖现有分区工具的布局模型，再补充自定义设置界面。该方向可以减少部分基础工作，但已有工具通常以拖动吸附为核心，和本项目明确要求的“窗口在哪里就属于哪个区域”以及区域级最大化并不完全一致，行为冲突会抵消复用收益。

## Recommended Approach

选择 Approach A。

核心运行模型：

1. 读取当前显示器工作区，按比例分割树生成矩形区域。
2. 观察普通顶层窗口的位置和状态，不主动移动普通窗口。
3. 以窗口中心点判定当前区域。
4. 标题栏双击、系统最大化按钮和 `Win + ↑` 触发区域级最大化。
5. 区域级最大化记录原始位置和大小；取消最大化时恢复原状态。
6. 布局应用后，重新计算已最大化窗口的区域边界；普通窗口保持原处。
7. 全屏程序、系统窗口、弹窗、置顶工具窗口和 UAC 安全桌面不参与管理。

## Settings and Presets

设置窗口以预览为中心：

- 预览当前显示器和矩形分区。
- 拖动分割线调整比例。
- 显示设置窗口所在显示器工作区的实际像素宽高，并在预览和设置区域中显示各区像素尺寸。
- 对当前的垂直分区，允许直接输入各区域宽度（像素）；所有区域宽度合计必须等于工作区宽度。
- 提供左右均分、`4/5 + 1/5`、三列等内置预设。
- 用户可以将布局另存为自定义预设、删除自定义预设并设为默认。
- 设置修改先预览，点击“应用”后生效；“取消”恢复旧布局。
- 设置界面低保真线框：`docs/designs/assets/settings-wireframe.html`。

## Tray and Startup

- 开机启动后默认隐藏到托盘。
- 托盘菜单：打开设置、暂停分区、恢复分区、退出。
- 暂停期间恢复 Windows 原生最大化行为；恢复分区后不主动移动普通窗口。
- 开机启动提供设置开关。

## Open Questions

- 需要在真实 Windows 10 环境验证不同窗口类型对最大化消息、全屏和 DPI 变化的差异。

## Success Criteria

首版通过以下验收：

1. 在 27 英寸显示器上创建 `4/5 + 1/5` 布局。
2. 浏览器位于右侧区域时最大化，只填满右侧区域。
3. 取消最大化后，浏览器恢复最大化前的位置和大小。
4. 拖动窗口跨越区域后，下一次最大化使用新区域。
5. 应用布局后，已最大化窗口跟随新区域边界，普通窗口不移动。
6. 重启 Windows 后应用自动启动并保留布局。
7. 托盘打开设置、暂停、恢复和退出均可用。
8. 分辨率或 DPI 变化后，比例布局仍能正确覆盖当前工作区。

## Distribution Plan

首版采用 Windows 便携包：发布可直接运行的构建目录或 self-contained 单文件版本，不引入复杂安装器。开机启动可通过用户设置写入当前用户启动项；后续如果需要普通用户分发，再增加安装器、卸载和更新流程。
